# Naming Convention for projects

To keep our test documentation structured, we use the following format for documentation in our projects

**Format**: `[PROJECT]-[TICKET_TYPE]-[MODULE]-[NUMBER]`

*   **[PROJECT]**: Project code name (e.g., `SMP` for SkyMp).
*   **[TICKET_TYPE]**: Сode name for the type of work performed:
   
| Code | Definition |
| :--- | :--- |
| `TC` | *Test Case* |
| `BUG` | *Bug-report* |
| `TP` | *Test-Plan* |
| `AS` | *Assets* |
| `REP` | *Report* |
| `ST` | *Smoke-Tests* |

*   **[MODULE_TYPE]**: Short module identifier (e.g., `AUTH` for Authentication, `UI_LANGUAGE` for Language Interface, `UI_FRONT` for Interface frontend).
   
*   **[NUMBER]**: Document identification number (e.g., `001`, `002`).

**Example**:

`SMP-TC-AUTH-001` -> SkyMp, Test Case, Authentication Module, Test Case 001.
